
## The listing comes in parts

This product is too large for one session to see every file, so its source listing comes in parts, one session per part, in turn. You are given one part's files, every source folder of the whole repo (with sizes, not files) so you can see the product whole, and the areas the earlier parts already named.

- **Group by promise across every part, never by part.** A part is only where the listing was cut. The server half of a promise may sit in one part and its client half in another.
- **Put a file in an area so far when it keeps that area's promises.** Name the area exactly as it is listed, and give only this part's files in its `sources`; its promise may stay as it is (repeat it) or be sharpened to cover what this part adds.
- **Name a new area only for a family of promises none of the areas so far keeps.** When this part's files and a later part's will keep one family, name the area for the whole family, so the later parts can join it.
- `sources` name only files listed in this part: a folder ending with `/` holds the files of this part under it, never files in other parts.
- **The first part states the product.** The session of the first part gives `product` as the skill above says. A later part is given the product's promise the first part stated, above its files: it frames this part, and later parts do not restate it, so leave `product` out. A later part given no promise states the product itself.

Every file in this part must fall in exactly one area.
